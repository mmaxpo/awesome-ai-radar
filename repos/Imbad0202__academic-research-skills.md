### [v3.24.3](https://github.com/Imbad0202/academic-research-skills/releases/tag/v3.24.3) — v3.24.3 — An author letter in the user's language, a field analyst that names no…
<sub>2026-11-14 · today</sub>

> > **Reviewer, citation, and adapter repairs and one new reviewer output; no new skill or mode, and the prompt-level changes are unmeasured:** A `full` review now also writes the author a letter in the user's language beside the Editorial Decision Package. `scripts/check_author_letter.py` fails a quotation in the supported quotation marks that it cannot find in the manuscript, a machine line or internal id in the letter, and an item map that does not list each roadmap row once (#1078). The field analyst lists what it read before the Reviewer Configuration Cards (#1075), and the cards give checks with manuscript locations rather than conclusions (#1076); it no longer recommends journals or other venues and names a target only when the author has confirmed one (#1080). The Phase 1 checks count a Han or kana letter as 1 point and a word as 2, so a short Chinese or Japanese trigger is measured, and the manuscript-leak check finds a 24-point Chinese or Japanese passage copied from the manuscript unless the passage also occurs in a metadata-envelope value or the contract (#1077). Korean keeps the whitespace count. For text with no Han or kana letter after NFKC, both checks now run NFKC first, and the trigger count no longer counts a lone mark such as `—` as a word. The leak check has synthetic tests only; no rate on real reviews is measured. The reviewer claim check applies NFC before it matches a quotation (#1074). `citation_compliance_agent` edits the paper draft only in `full` mode, where its Corrected Draft now goes to Phase 6, and returns proposals in `revision` mode (#1068); its Phase Boundary block names both of its outputs (#1067), and standalone citation-check returns a report and rewrites the user's text only on request (#1062). The Zotero and Obsidian adapters send an item or note that fails the schema or a type check to the rejection log, instead of writing it to the passport or stopping the run; a Zotero `date` or `issued` that holds a number, such as `"date": 2024`, is now rejected, and all three adapters, `folder_scan.py` included, now need `jsonschema`. No real Zotero export or Obsidian vault was run (#1055, #1056, #1058, #1059). Claude Fable 5.2 is a supported session model; it has a system-card audit and a routing smoke test, but no full pipeline run or reviewer calibration (#1063).
> **Added**
> - **A `full` review also gives the author a letter in the user's language, beside the decision package (#1078).** The Editorial Decision Package serves two readers: the author, and the checker and later stages, which need its machine lines and ids (`dimension_verdicts:`, `fired_conditions:`, transport refs, `REV-<n>`, `SC-<n>`). Its section headings are fixed in English, so a user who writes in another language got prose in that language under English headings, with many unexplained ids. After the package is complete, the dispatching session now writes a separate author letter by `academic-paper-reviewer/templates/author_letter_template.md`: the decision and its main reasons, strengths, every required and suggested change with its location, questions for the authors, and an appendix with how the review was run, its limits, the reviewer summaries, the advisory checks, and an item map from the letter's numbers to the roadmap's transport refs. The letter's headings and prose are in the user's language (a quotation keeps the manuscript's language), and machine lines and internal ids stay out of the whole letter, with bare transport refs only in the appendix's item map. The letter's inputs are the package, the Phase 0 Coverage section, and the Phase 2 reports for strengths and questions only. New `scripts/check_author_letter.py` fails a quotation that is not in the manuscript, a machine line or id anywhere in the letter, including one written beside CJK text or inside Markdown emphasis or code, and an item map that does not list each roadmap row once or holds a table row outside its one table. It checks quotations with the reviewer claim check's own quotation marks (`“…”`, `"…"`, `‘…’`, `「…」`, `『…』`) and manuscript match (#1002), as #1078 asks: a quotation may wrap within its paragraph or list item, also inside a blockquote, NFC is applied (#1074), case is folded, each whitespace run is one space, the double quotation marks `"` `“` `”` are removed, and `‘` `’` read as `'`; `「」`, `『』`, and other marks are kept. That match does not check whole words, reads no other quotation marks (« », „ “), reports as not found a quotation whose text wraps between two CJK characters, in the letter or in the manuscript file, and can pair an empty or unpaired mark with the wrong mark, so the words after it go unchecked; the template asks for exact copies on one line in `“…”` or `「…」` only, in every language. It reads the letter's last level-2 heading as the appendix and the appendix's last level-3 subsection as the item map, which always holds a two-column table with a header row and a delimiter row, outer pipes optional, in any language, and every row of which is an item number from 1 and then a ref; it does not compare the item numbers with the body's numbered changes. After one correction pass, a problem still left is named, by kind, in one line under the letter's title. Bare transport refs (`R1`, `S1`) are not searched for, because a manuscript location such as "Table S1" has the same form. The package does not change; the three attachment sections now say that the calls that write the decision, roadmap, and Editorial Decision Letter do not see an attachment, and the author letter names attachment results only in its appendix. `check_panel_synthesis.py`, re-review, the revision coach, and `academic-pipeline` still read the package, not the letter. Prompt-level; the effect on readability is unmeasured.

### [v3.24.2](https://github.com/Imbad0202/academic-research-skills/releases/tag/v3.24.2) — v3.24.2 — An honest null for experiment locks, repro_lock alignment, and a corre…
<sub>2026-11-06 · 8d ago</sub>

> > **Repairs and docs; no new skill or mode, and the prompt-level changes are unmeasured:** An `experiment_provenance[]` entry can now say it has no honest lock values, with `repro_lock: null` and a `repro_lock_reason` (#1049). A survey or an analysis with no LLM could pass before only with placeholder values. Earlier ARS releases reject this form, so a passport that uses it needs this release. `check_repro_lock.py` now fails a required value that breaks its field's type or value rule, such as a null model id; `cross_model.secondary_model_id` may still be null. `planned_vs_executed[].value` accepts only a number or a string, so some passports that passed before now fail (#1050). The `sr-screener` methods text no longer says the reviewers could read only the record file: the tool list removes web and write access, and reading only the given file is an instruction (#1039). SETUP records two checks in which an uploaded skill dispatched a built-in sub-agent in a conversation after a retry; multi-agent stages stay untested (#1040).
> **Fixed**
> - **An experiment with no honest lock values can say so (#1049, PR #1051).** Every `experiment_provenance[]` entry had to fill every `repro_lock` field, and those fields describe LLM and ARS run settings. A survey, an analysis with no LLM, or a trained model with no ARS prompts could pass only with placeholder values. The key stays required. Its value may now be `null`, and `repro_lock_reason` is then required; a reason beside a populated lock is rejected. The reason is free text: it discloses the gap, does not prove the lock does not apply, and no script checks the details it names. The passport-level validator and the required-field set do not change. **Compatibility:** earlier ARS releases reject `repro_lock: null` in an entry, so a passport that uses it needs this release.
> - **`repro_lock` docs, example, gate, and validators agree (#1050, PR #1052).** `check_repro_lock.py` now checks each required value against its field's type or value rule, matching the nested entry schema. `cross_model.secondary_model_id` may be null or any string, and the other string fields must be non-empty. A drift test compares the two on required keys, supported values, and a fixed set of wrong and edge-case values, not on every possible value, and extra keys stay the one known difference. The example passport gains a passport-level lock, and its two trained-model experiments use `repro_lock: null` with a reason. The D7 text in the integrity gate names 3.12.0 as the boundary and adds a fifth FAIL condition, a post-#260 passport with status `legacy_unknown`. The pattern doc no longer says a version change alters the prompt hashes, because they hash only the prompt files. **Compatibility:** a populated lock with a required value that breaks these rules now fails when `check_repro_lock.py` is run on it, and `planned_vs_executed[].value` accepts only a number or a string. Some passports that passed before now fail. The gate text is prompt-level and its effect is unmeasured.
> - **The `sr-screener` methods text states what the tool list enforces (#1039, PR #1043).** `tools: Read, Grep` removes web and write access but does not confine Read and Grep to one file. The title/abstract and full-text methods text now say: "The reviewer agents had read-only file tools and no web access; each was instructed to read only the file it was given." Methods text generated by an earlier release keeps the old sentence, so an author who used it should correct it by hand.

The second sends each weakness and each CRITICAL or MAJOR Devil's Advocate row, without its seat label, to a subagent of the session model, which says whether the manuscript contradicts it. It is on by default, and `ARS_PANEL_CLAIM_CHECK=0` turns it off. Neither attachment feeds the decision, the revision roadmap, or re-review criteria. Before the second check shipped, a preregistered held-out audit of 805 panel claims put the false-claim rate between 1.5% and 12.9%, and Claude Opus 5.5 and Claude Fable 5.1 passed its contrast gate as judges. The write-scope guard launcher starts one Python process per tool call instead of three, which should cut the Windows AppXSvc leak to about a third, although the Windows behaviour is untested here (#1015), and the guard's notes state which tool names it checks (#1022). Three integrity-check rules now agree on Stage 5 entry, report freshness, and Stage 4′ (#1011), and the startup notice appears only when an update is available (#1027). Outside users reported #1015, #1022, and #1027.
> **Added**
> - **The Editorial Decision Letter carries a check of the references the panel suggests (#1001).** Reviewer 2 and Reviewer 3 now repeat each specific work they recommend in a `yaml suggested-references` block (title, and authors, year, DOI, or arXiv ID when they can attest them; `[]` when they name none). After the decision, the dispatching session runs `scripts/verify_panel_recommendations.py` on their saved reports and appends its table under `## Attachment: Suggested-Reference Check (advisory, #1001)`, before the acronym check, which stays the letter's last write. The script looks each work up through `verification_gate.verify_citation` with the four resolver clients of `verify_passport.py`, live and without the verification cache, and reports one of four results under the citation gate's C-V6(a) rule: found, DOI or arXiv ID not found, title not matched with no identifier to check, or not checked because an index that could settle it did not answer or the lookup failed. "Found" shows only that a record exists, not that the work supports the recommendation. Like the acronym check, the attachment is script output: the decision, the revision roadmap, and re-review criteria do not draw on it, and a suggestion it cannot find stays in the roadmap as the reviewer wrote it. `docs/DATA_FLOWS.md` names the new network use, and `shared/contracts/degradation_registry.json` adds its two degraded states. Tests use mocked resolver clients and synthetic reports; whether reviewers write the block, and how often their suggestions resolve, are unmeasured.
> - **A preregistered held-out audit of the review panel's claims against the manuscript (#1002, part one).** `evals/heldout/panel_claim_factuality/` takes the 805 weaknesses and Devil's Advocate CRITICAL and MAJOR rows of the 17 score-eligible E4 panels, with the seat held back (`scripts/extract_panel_claims.py`), and `scripts/dispatch_panel_claim_audit.py` sends them to two judges, gpt-6-astra through codex and Gemini 4 Argon at medium thinking through the paid API under a spend cap, two replicates each. Both judges passed the contrast gate: each marked all 51 false contrast sentences false and none of the 51 accurate twins. The two judges agreed on 12 false claims, in 6 of the 17 panels, which meets the preregistered bar for planning part two; the other 92 claims (54 on which the judges diverged, 38 on which a judge's verdict was unresolved because its replicates differed or a false verdict failed the evidence check) were not adjudicated, so the false-claim rate is reported only as a range, 12/805 (1.5%) to 104/805 (12.9%), and no per-seat rate is computed. No person verified the 12 claims. The plan reached version 9 through recorded amendments; the scoring run is version 8 (Gemini outputs from that run, codex outputs from version 3, reused by prompt hash), and version 9 changes only the transports, under which those outputs score the same. The transports run on POSIX systems only (tested on macOS). No ARS skill, agent, or pipeline step changes.
> - **Claude Opus 5.5 and Claude Fable 5.1 pass the #1002 contrast gate (#1002, plan version 10).** Part two of #1002 would use the session model as its judge only after that model passes the part-one contrast gate. `scripts/dispatch_panel_claim_audit.py` gains two contrast-only judges, `claude-opus-5-5` and `claude-fable-5-1`, each through `claude -p` at high effort with no tools and no MCP servers, an empty configuration directory, an allowlisted environment, and a temporary working folder that the script checks for project settings and git checkouts in it and every folder above it. The `--contrast-only` run sends only the 61 batches that hold a contrast sentence, and the `contrast-score` command applies the preregistered bars. Each model, in two replicates, marked all 51 false contrast sentences false and none of the 51 accurate twins. Claude Opus 5.5 wrote those sentences, so the test cannot separate judging skill from familiarity with them; gpt-6-astra passed the same sentences in part one. Their verdicts on reviewer claims are not scored, and no ARS skill, agent, or pipeline step changes.
> - **The Editorial Decision Letter carries a check of the panel's findings against the manuscript (#1002, part two).** After the decision and the suggested-reference check, the dispatching session runs `scripts/audit_panel_claims.py prompt` on the manuscript and the five saved Phase 2 reports, sends the written prompt, unchanged, to one subagent of the session model with no tools, and runs `render` on the reply. The attachment, `## Attachment: Reviewer Claim Check (advisory, #1002)`, lists a finding the judge marked as contradicted only when the judge's quotation passes the script's check against the manuscript, and says that the check reads only the quotation's words, not its location or whether it contradicts the finding; other false verdicts are listed as not confirmed, and missing verdicts or a report that cannot be read make the coverage partial.
